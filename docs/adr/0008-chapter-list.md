# 0008. 书架的每一行加一个「步骤」图标，用来跳章

- 状态：已接受
- 日期：2026-09-23
- 相关：ADR-0007（书单不禁用鼠标）

## 背景

跳章一直只有 `←` `→`（或 `[` `]`），一次跨一章。而本项目的目标读物是长篇中文小说 ——
文档里自己举的例子就是 `[3/512]`。**从第 3 章到第 300 章要按 297 次**，这条路实际上等于没有。

数据层其实早就备好了：`storage.listChapterTitles` 能取出一本书的全部章节标题，
`app.listChapterTitles` 也已经接到客户端 API 上 —— 但全项目**没有任何地方调用它**。

## 决定

**点书架的整行 = 选中这本书开读**（续读上次的位置，与原来完全一致）；
**行右侧多一个 `≡` 图标按钮 = 展开这本书的步骤清单**。

这样加而不是改，是因为"点一下就能接着读"是这个界面的主路径，不该为了跳章把它换成两步。

步骤清单的形态：

```
云中记                                    3/512
✓ 第一章 山雨                                1
✓ 第二章 亭子                                2
▸ 第三章 山雨欲来                             3
· 第四章 夜行                                4
· 第五章 …
← back                    space page · l close
```

要点：

- **伪装成「recent tasks」里某个任务展开后的步骤清单**：读过的画 `✓`、当前这条用 `▸`、
  右边是步骤序号。屏幕上没有"章"字，也看不到正文。收缩/展开待办本来就是这种形状。
- **打开时把当前章滚到视野中间**。几百章的书如果落在第 1 章，每次都要往下滚三百行，
  那和没有这个功能是一样的。
- **滚动用浏览器默认行为**。`StreamBody` 的按键处理在 `covered` 时会在 `preventDefault`
  之前返回，所以方向键、空格、滚轮在这个界面上都是原生滚动 —— 不需要自己再实现一套。
- **点任一条 = 跳到那一章并开始读**。目标书不是当前打开的书时同样成立（`goToChapter`
  本来就接受任意 book）。
- `null / books / chapters` 是**一个互斥状态**而不是两个布尔量：这两个界面不可能同时成立，
  用两个标志迟早会构造出"两个都开着"这种没有意义的状态。
- 章节目录和书架一样属于 ADR-0007 说的"要用鼠标的界面"，所以打开它时鼠标同样不参与收场。

## 考虑过但没选

- **数字直跳**（读书时敲章号 + Enter）：精确、几乎零暴露，但要求用户知道章号 ——
  而"我记得大概在第几章附近"正是需要浏览章节名的时候。
- **`Shift` + 方向键一次跨 10 章**：零界面，但从第 3 章到第 300 章仍要约 30 次，只是把
  297 变成 30，没有解决"想直接到某处"这件事。
- **按住 `←` `→` 加速**：键盘重复速率不可控，会冲过头。

两者将来都可以作为补充加上，不冲突。

## 后果

- **多了一层可见的小说文本**。书架暴露的是书名，章节目录暴露的是**章节标题**——对认识
  这本书的人来说，标题比书名更容易认出来。这是拿到跳章能力的代价，也是这个项目里
  单次暴露面积最大的一个界面。
- 因此：目录是**按需展开**的（不是常驻），打开时会自动落在当前章而不是从头开始，
  并且 `← back` 一步退回收起的书架。
- 章节标题只在目录打开时才去读，不在打开书架时全量捞出来。
