# ADR 0001 — 实现为纯客户端插件，不引入服务端

- 状态：已接受
- 日期：2026-09-22

## 背景

DSH 插件可以有两半：宿主（服务端）半与客户端（浏览器）半。书籍解析、书架存储、阅读界面都是浏览器内可以完成的工作，但"能放进服务端"的诱惑在于：服务端能读工作区文件、能被 AI 工具访问、能跨浏览器共享。

## 决策

本插件**只有客户端半**，不注册任何服务端能力。

宿主半只保留一件事：注册 settings 命名空间（DSH 的持久配置要求宿主半注册同名命名空间，客户端侧才能读写，见 `docs/dsh-client-plugin-notes.md` §5）。这不构成"服务端功能"。

## 理由

1. **浏览器的文件选择器能读用户硬盘上任意位置的文件**，而宿主半受 DSH 文件沙箱限制（本会话的沙箱模式是 `workspace-write`，工作区外的读取需要审批）。导入一本书却要弹审批提示，与"隐蔽"这一根本目标直接冲突。
2. **书的内容不应该进入工作区**。把小说正文落到工作区目录，会让它出现在文件浏览、git 状态、AI 的上下文里——这些都是暴露面。
3. 纯客户端意味着零配置：装上即用，不需要用户理解工作区、路径或沙箱。

## 代价

- 书与进度存在浏览器存储里，**换浏览器或清缓存就没了**，无法跨设备同步。
- **无法与 AI 联动**（例如"帮我总结这一章"）。
- 无法从工作区目录批量导入。

这三条都被明确接受：本项目是个人自用工具，不是书库服务。

## 被放弃的替代方案

- **服务端解析 + 客户端展示**：可以在工作区放一个书库目录，但会引入沙箱摩擦和正文落盘这两个暴露面，收益（跨设备、AI 联动）不在当前目标内。
- **两半都做**：范围翻倍，且服务端半会带来上面全部代价，只是多一个能力——用户没要求它。
