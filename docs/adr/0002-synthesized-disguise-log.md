# ADR 0002 — 隐藏态用"合成日志"，不用真实会话镜像

- 状态：已接受
- 日期：2026-09-22

## 背景

"隐藏着看小说"需要一个隐藏态：按下切换键后，屏幕上应该剩下看起来像"用户正在正常使用 DSH"的东西。当天设计树上有两条候选：

- **合成日志**：写一串通用文本（"Analyzing… Running tests…"），让它缓慢滚动。
- **真实会话镜像**：取用户真实的会话数据渲染出来，看上去就是本人正在用的那个界面。

用户选择了合成日志，但明确要求**日志里要包含真实会话的标题与消息正文片段**，理由是纯通用文本"太假"。

## 决策

隐藏态渲染**合成的**日志流：它由真实会话数据**取材**，但不是真实界面的镜像。

取材边界（这是本决策的核心，比"用不用真实数据"更重要）：

| 取 | 不取 |
| --- | --- |
| 当前会话 + 最近 N 个会话的**标题** | 完整消息正文的渲染 |
| **工具名统计**（如 `Read × 12 · Bash × 5`） | 工具调用的参数与结果全文 |
| 最近几条消息的**短片段**（裁剪到一行以内） | 任何路径、URL、密钥等结构化内容 |

时间点：**只在进入隐藏态的那一瞬间取一次快照**，之后不再读取、不轮询。

失败回退：取不到会话数据（新会话、无历史、读取失败）时**静默退回通用模板**。隐藏态**绝不能白屏**——白屏是比暴露小说更糟的结果。

### 数据来源（2026-09-22 实测确认）

三条来源全部验证可用，且都在**客户端**、不触碰宿主文件系统：

| 数据 | 读取路径 | 实测结果 |
| --- | --- | --- |
| 会话标题 | `ctx.sessions.list.getSnapshot()` → `SessionListState.byId[].displayTitle` | 505 个会话，`phase=ready` |
| 消息片段 | `ctx.sessions.binding(id).eventSource.getSnapshot().entries` → `assistant/message` / `user/message` | 761 条事件，文本可提取 |
| 工具名统计 | 同一事件窗口里的 `tool/call` 事件 | 事件类型清单确认存在 |

实测到的事件类型：`assistant/message`、`tool/call`、`tool/result`、`step/end`、`step/start`、
`approval/asked`、`approval/decided`、`todo/write`。

**注意 `displayTitle` 的回退链**是 `durable title → 项目目录名 → 会话 id`：
它"总有值"，但退化成目录名时等于把真实工作路径打在屏幕上。所以标题必须过一遍路径过滤。

**工具名统计是三者中风险最低的**（只有工具名与次数，没有内容），
它是本 ADR 里优先落地的数据源；正文片段是最高的那一档，用设置项控制。

## 理由

1. 真实镜像要求渲染真实会话数据结构，会随 DSH 内部结构变化而反复损坏；合成日志的输入面只有一个很小的数据子集，健壮得多。
2. 片段 = 逼真度，镜像 = 逼真度 + 一大堆耦合。用户的诉求是"看起来像在干活"，片段已经满足。
3. 快照一次而非持续读取，意味着数据在隐藏态期间不会继续变化——一个"日志在缓慢滚动但内容不更新"的外观比"内容跟着你的真实操作跳动"更安全，也更省事。

## 被明确接受的风险

**正文片段会把用户正在处理的真实工作显示在屏幕上。** 在共享屏幕的场景下，这可能比暴露小说更糟。用户已知悉并选择接受（要求"更逼真"）。

缓解手段：片段长度上限、单行显示、总行数上限，以及设置项允许关闭正文片段只留标题与工具名统计。

## 被放弃的替代方案

- **纯通用文本**：零泄露风险，但用户判定"太假"，伪装壳的可信度不足——而伪装壳不可信就等于这个功能没做。
- **真实会话镜像**：逼真度最高，但耦合 DSH 内部结构，且需要读完整消息正文，与"最小数据面"原则相反。
