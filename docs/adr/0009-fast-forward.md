# 0009. 快进：Shift + 前向方向键让输出的时钟走快

- 状态：已接受
- 日期：2026-09-23

## 背景

逐字输出的节奏是这个项目的伪装本体 —— 屏幕上看起来是 AI 正在生成内容。但它同时也是
"想读快一点"时唯一的阻碍：一章按 `DEFAULT_TEMPO` 要跑几十秒。

而且**滚动救不了这件事**。视口恒在已输出内容的底部自动跟随（ADR-0004 的进度语义也依赖
这一点），所以没输出的字滚也滚不出来 —— 往下滚只会撞到"还没生成"的那条线。想让内容更快
出现在屏幕上，唯一的办法是让**输出本身**变快。

## 决定

`Shift` + `↓`（或 `→`）＝ 快进。

做法上刻意**不是"跳字数"**，而是**让虚拟时钟走快**：

| 做法 | 屏幕上看到 |
| --- | --- |
| 跳字数（把 `revealed` 一次推大） | 一整段文字**同时**出现。不像在生成，像有人在翻页 |
| **让时钟走快**（本条） | 文字仍然逐行、逐字长出来，只是快 —— 看上去仍是"在生成" |

实现只有两处：

- `typing.ts` 的 `advanceClock`：把每 tick 的真实时长乘以倍率再加进**虚拟时钟**，
  每行的时间预算原封不动。所以快进的只是整体速度，不是"这一行不要了"。
- `reading.tsx` 的 tick 循环：从"每 tick 重算 `Date.now() - begin`"改成累加虚拟时钟 ——
  快进要做的正是让这个时钟走快。

两条参数（`typing.ts` 的 `FAST_FORWARD`）：

- `rate: 12` —— 按住期间时钟走 12 倍。一章几十秒的内容变成几秒。
- `windowMs: 600` —— 一次按键让快进持续 600ms。键盘自动重复会不断刷新它，所以
  **按住**就是持续快进；同时它让**点一下**也拿到一小段快进（点一下快进一段、按住就一直快）。

只重定义**前向**那一对（`↓` `→`）。`Shift`+`↑` / `Shift`+`←` 沿用原来的滚动与翻章 ——
`Shift` 本来就不在 `resolveReadingKey` 的排除列表里，所以这个改动只影响两个"往前走"的组合。

## 后果

- 快进**不破坏伪装**：它看起来只是"这次生成得比较快"，而不是"有人跳过了等待"。
- 代价是它**没法真正跳过**：真想让整章瞬间出现是做不到的，那是刻意的（见上表）。
  读到不想看的段落时，快进是最快的可用手段。
- 快进在 `durationMs` 处封顶（`advanceClock` 的上界），所以它最多把本章推完，
  不会溢到下一章的坐标里。
- 快进状态放在 `ref` 而不是 `state`：它每 `TICK_MS` 被读一次，进 state 会让组件
  每 tick 重渲染一遍，而它本身不该触发任何渲染。
